Coauthoring (real-time editing transport)

The browser editor connects to the document server over Socket.IO / Engine.IO (since ONLYOFFICE 7.3). sdkjs builds the URL from the document key and server version.

GETPOST {{.CoauthoringVersioned}}

Primary path used by current sdkjs builds: /{version}/doc/{key}/c/?EIO=4&transport=polling

GETPOST {{.CoauthoringUnversioned}}

Legacy-compatible path without version prefix (also accepted).

  • GET …?transport=polling — open session / long-poll receive (packets 0, 40, 42)
  • POST …?transport=polling&sid=… — send auth, saveChanges, isSaveLock, etc.

WebSocket upgrade: not implemented (HTTP 501). Polling transport is used.

Save flow (single-user)

Cell edits send getLock (server replies with granted locks) then saveChanges → unSaveLock. With customization.forcesave, the Save button sends forceSaveStart; the server replies and then forceSave after converting cache. Without forcesave: isSaveLock → saveChanges → unSaveLock, then callback status 2 or 6.

Integrator callback (Docs API)

Your app exposes editorConfig.callbackUrl. ONLYOFFICE POSTs JSON when the document should be saved. See callback handler.

When OFFICE_JWT_SECRET is set, bodies may be wrapped as {"token":"…"} (JWT_IN_BODY style).

4. Verdict — editor embed compatibility

For the standard open → edit → autosave → callback → persist flow described in the ONLYOFFICE how-it-works guides, go-office is API-compatible: the browser loads the same api.js, connects to the same coauthoring URL shape, reads/writes the same cache paths, and notifies your integrator via the same callback contract. Gaps are limited to optional admin APIs (command service, HTTP converter, WOPI), WebSocket transport, and multi-user co-editing.

Evidence: go test ./... (protocol unit tests + golden WS fixtures); Playwright tier-1 open-formats, content, and save specs against live sdkjs. Full audit (conversion, command, WOPI, callback field gaps, legacy paths): api.md.
